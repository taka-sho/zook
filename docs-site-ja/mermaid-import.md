# Mermaidフローチャートのインポート

[🇬🇧 English](/zook/mermaid-import/){ .md-button }

[Mermaid](https://mermaid.js.org/)の`flowchart`/`graph`記法で書いた図を、zookのYAMLに変換できます。ノード・矢印・入れ子グループというMermaidフローチャートの構造は、zook自体のコンテナ・ノード・リンクという基盤エンジンとほぼそのまま対応するため、変換後は`validate`/`build`/`export-drawio`/`sync`という既存のパイプラインにそのまま接続できます。

対応するのは`flowchart`のみです。`sequenceDiagram`のような縦のライフライン・時系列メッセージを描く図は、まったく別の描画エンジンが必要になるため、現時点では対象外です。

## 基本フロー

```bash
zook from-mermaid diagram.mmd -o diagram.yaml
zook validate diagram.yaml
zook build diagram.yaml -o diagram.pptx
```

`from-mermaid`は変換後のYAMLを`build`/`validate`と同じ検証(スキーマ・重なり・リンク経路など)にかけてから書き出すため、Fatal/Warningはこの時点で分かります。`--format json`/`github`にも対応しています。

## 対応している記法

- ヘッダー:`flowchart <TD|TB|BT|LR|RL>`、または`graph <...>`(レガシー別名)。`TD`/`TB`/`BT`(と Mermaid の `v`/`^`)は縦方向、`LR`/`RL`(と `>`/`<`)は横方向のレイアウトに対応します。ヘッダーや方向を省略した場合(`flowchart` だけの行を含む)は縦方向として扱います
- `;` は Mermaid の文法どおり文の区切りとして扱います。`graph TD;` / `A-->B;` も、`graph LR; A-->B; B-->C` のような1行の書き方も使えます。ラベル内の `;`(`A["x; y"]`、`-->|a;b|`)はラベルの一部です
- ノード形状:`id[label]`(四角)/`id(label)`(角丸)/`id{label}`(ひし形)/`id((label))`(円)。Mermaid のそれ以外の形状は、この4つのうち最も近いものに置き換えます。`([stadium])`・`[(database)]` は角丸、`[[subroutine]]`・`>asymmetric]`・`[/parallelogram/]`・`[/trapezoid\]` は四角、`{{hexagon}}` はひし形、`(((double circle)))` は円です。引用符で囲んだラベル(`A["[括弧] や --> を含むテキスト"]`)はそのまま文字として扱い、`:::className` は無視します。矢印の中にしか登場しない `id` は、`id` 自体をラベルとした四角ノードとして自動登録します。同じノードを何度か宣言した場合は、Mermaid と同じく最後に明示したラベル・形状が使われます
- Mermaid 11 の形状指定:`id@{ shape: cyl, label: "注文DB" }` も括弧の記法と同じように読みます。円柱・スタジアム系は角丸、`hex` はひし形、円の仲間はすべて円、それ以外(`doc`、`lean-r`、`notch-rect` など)は四角です。エッジの id(`A e1@--> B`)も書けます。エッジ自体に付ける `e1@{ animate: true }` の文は無視します
- ラベル:`<br>`/`<br/>` は改行に、`#quot;`/`#35;` のようなエンティティは元の文字に変換し、markdown 文字列(`` "`**太字** のテキスト`" ``)は記号を除いた文字列にします
- 矢印:`-->`、`---`、`<-->`、`-.->`、`-.-`、`==>`、`===`、`<==>`、`--x`、`--o`、`x--x`、`o--o` と、その長い形(`---->`、`-..->`)に対応します。矢じり(`>`、`x`、`o`)はその端の zook の矢印になります。点線・太線は通常の線と同じ見た目で描きます(線種は再現しません)。`~~~`(非表示のリンク)は線を描きません。ラベルは `-->|label|`(パイプの前に空白があっても可)または `-- label -->` / `== label ==>` / `-. label .->` で付けられます。`A & B --> C & D` は組ごとに1本ずつリンクを描き、1行に矢印をつなげる書き方(`A --> B --> C`)にも対応しています
- `subgraph <id>[<Title>]` 〜 `end`:入れ子にも対応しています。`[<Title>]` を省略した場合は、Mermaid と同じく subgraph に書いた文字列そのものがタイトルになります(`subgraph Backend`、`subgraph "AWS Cloud"`、`subgraph バックエンド`)。subgraph の中に `direction LR` などを書くと、その subgraph だけ配置方向を変えられます。ノードは、そのノードに言及した subgraph のうち最初に閉じたもの(入れ子なら内側)に属し、最上位でしか言及されないノードは最上位に置きます。そのため `A --> B` のあとに `subgraph S` 〜 `B` 〜 `end` と書くと、Mermaid と同じく `B` は `S` の中に入ります。リンクの接続先には、あとで宣言する subgraph の id も指定できます
- `end` が subgraph を閉じるのは Mermaid と同じく小文字のときだけです。`End`/`END` はノード id として使えます
- `%% ...`のコメント行は無視されます。全体を囲む ```` ```mermaid ```` のコードフェンス、`---` のフロントマター、複数行の `%%{ ... }%%` ディレクティブ、`accTitle:`/`accDescr:` のアクセシビリティ用テキストも無視します
- zook が読めない文は、該当行を示すエラーになります。文が黙って消えることはありません
- **分岐のあるグラフはランク(段)で配置します。** 1つのスコープ(最上位や subgraph)の中でリンクが枝分かれ・合流している場合、各ノードをリンクの流れに沿った段に置き、同じ段のノードは枠線のない行(`LR` なら列)に並べます。段の中の並びは、交差が減る順にします。分岐のない単純な連鎖は1列のまま、リンクの向きの順に並べます(`F --> J` より前に `J --> K` と書いても F、J、K の順になります)。別々の連鎖どうしはソースの順序のままです。生成される最上位のコンテナには枠線を付けません

## 既知の制約(v1)

- 段の配置は簡易なもの(最長経路と1回の並べ替え)です。交差するリンクが多い図では、そのあと `zook doctor` や [draw.io連携](drawio-sync.md)のループでの調整が必要になることがあります
- 点線・太線は通常の線と同じ見た目で描かれます。線種の違いは再現されず、矢じりの `x`/`o` も通常の矢じりとして描きます
- 四角・角丸・ひし形・円以外の形状は、この4つのうち最も近いもので近似します
- `classDef`/`class`/`style`/`linkStyle`/`click`などのスタイル・インタラクション用ディレクティブは無視されます
- 最上位に書いた `direction` 文は、Mermaid と同じく無視されます(グラフ全体の向きはヘッダーで決まり、`direction` は subgraph の中で使います)
- `sequenceDiagram`など`flowchart`/`graph`以外のMermaid図種別は、その旨のエラーになります

## プレーン図形ノードについて

`from-mermaid`が生成するノードは、アイコンではなく`nodeStyle.shape`(`rect`/`rounded`/`diamond`/`circle`)を使った「図形内部にラベルを描く」ノードです。これはMermaid変換専用の機能ではなく、手書きのYAMLでも使える汎用のノードスタイルです。詳細は[YAML入力仕様](yaml-guide.md)を参照してください。
