# 既知の制約(v1)

archdiagram は「PowerPoint 手編集の起点として十分な図」を目標としており、完全自動の美麗レイアウトは目指していません。v1 時点での既知の制約は以下の通りです。

## 自動レイアウトは重なり回避をしない

座標未指定の要素は grid/horizontal/vertical で自動整列されますが、既に座標指定された兄弟要素を避ける処理は行いません(第一版仕様)。狭い間隔でリンクラベルとノードラベルが近接すると、視覚的に重なる場合があります。生成後に PowerPoint 上で位置調整することを前提としています。

## コネクタは矩形図形限定

接続対象(アイコン画像・コンテナ枠)はすべて矩形として扱われます。python-pptx のコネクタ実装自体が矩形以外では安定動作を保証していないためです。

## コネクタラベルは移動に追従しない

OOXML スキーマ上の制約により、リンクラベルは独立したテキストボックスとして中点に配置されます。生成後に図形を大きく動かした場合、ラベル位置は追従しません(詳細は[内部設計メモ](design-notes.md#connector-labels))。

## アイコンはプレースホルダー

同梱のアイコン画像は AWS 公式アイコンではなく、自作のプレースホルダーです。実運用では [アイコン・レジストリ](icons.md#icon-assets) の説明に従い、公式アセットに差し替えることを想定しています。

## マルチクラウド未対応

YAML スキーマ・レジストリ形式自体は `provider` によるマルチクラウド拡張を見据えていますが、v1 で組み込みレジストリが用意されているのは AWS のみです。GCP/Azure 用レジストリの追加は次版スコープです。

## 大量バッチ生成は想定外

1回の実行で数十枚以上のスライドを生成するような用途は想定していません(1 YAML = 1 スライド、週1〜月2回程度の利用を想定)。
